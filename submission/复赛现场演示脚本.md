# LabOps Guard 复赛现场演示脚本

建议时长：4 分钟。主画面使用只读 Trust Dashboard，PPT 负责定位和架构过渡。

## Preflight

- 页面显示 Trust Contract v1、Trust State Machine v1 和 `Read-only`。
- 证据链顺序为 Identity → Policy → Execution → Evidence → Audit。
- 页面没有综合评分以及执行、修改、审批入口。
- AT-004 为 `PASS / RESOLVED`；危险分支为 `POLICY_VIOLATION / ROLLED_BACK`。
- Trust Evaluation Suite 报告为 10 案例，且明确写出适用边界。

## 0:00–0:30｜真实实验室流程与 Agent 信任问题

“一次评测漂移通常要经过值班发现、工程师找证据、研究员讨论、负责人审批、修改重跑和独立
复核，成本来自人工接触、消息往返、重复运行与证据整理。当 Agent 承担这些工程动作，我们需要
证明它是谁、为什么获准行动、执行了什么，以及谁独立验证结果。LabOps Guard 是面向生产级
Agent 系统的可信基础设施参考实现。”

## 0:30–1:10｜Trust Layer

“Trust Contract v1 统一 Identity、Skill、Policy、Execution、Evidence 与 Audit；Trust
State Machine v1 固定审批、执行和裁决顺序。六个 Agent 各有权限边界，七个 Skill 可查询、
可校验。异常恢复使用独立 append-only attempt overlay：有限 retry、真实证据 reassign 和真人
takeover 都不能绕过 Auditor。Dashboard 逐域展示检查与证据来源，不生成综合评分。”

## 1:10–1:45｜危险分支

展示 metric.py 越权修改。说明保护资源变化被策略与哈希检查识别，Runner 不接受该方案，
Auditor 保持 `POLICY_VIOLATION / ROLLED_BACK`，终态不得写为 `RESOLVED`。

## 1:45–2:45｜AT-004 合法分支

展示 `71.875% × 3` 基线、10 条带哈希事实、单变量计划与执行前人工批准。Safe Executor 只
提交获批 Tool Contract；ApprovalGrant 强绑定计划哈希、范围、保护资源、预算、时效和 nonce，
不一致或重放即 fail closed。断网 CPU Runner 在新沙箱恢复 preprocessing profile。候选三次为
`97.8124976% × 3`，六组保护哈希不变。

## 2:45–3:25｜Evidence 与 Independent Audit

展示 raw stdout、metrics、manifest、审批时序、保护哈希和 7-entry Trace。Auditor 不采信
Executor 自述，独立得到 `CHAIN_OK / ACCEPTED` 与 `PASS / RESOLVED`。Evidence Bundle 有
27 entries，SHA-256 为
`4092b43f39df52db3847caa28ca01e4321129a1c17ec7ca5efd2029ab1fb77cd`。

## 3:25–4:00｜Trust Evaluation Suite 与边界

“10 个治理案例中，策略越权阻断率和独立审计准确率为百分之百，错误关闭率为零。输入与
Oracle 分离；该结果只验证固定治理规则。当前实现是单机确定性 CPU Runtime，不宣称生产
身份、分布式调度、MCP Server、OTel 后端或全场景 MLOps 覆盖。”

最后展示 GitHub 与 Public Evidence Replay。

## Fallback

1. 本地 Trust Dashboard。
2. Public Evidence Replay。
3. 预录完整运行视频。
4. Evidence Bundle 离线验证与 Trust Evaluation Suite 报告。

Public Replay 和录屏都不能称为实时 AgentTeams 执行。任一契约、Trace 或哈希失败时，停止
成功故事并显示 `BLOCKED`。
