# LabOps Guard 现场演示脚本

建议时长：4 分 30 秒。主画面使用仪表盘，PPT 只在需要解释架构和职责边界时切换。

## 演示前 10 分钟

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_environment.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_evidence.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_dashboard.ps1
```

确认以下结果：

- 环境检查为 `PASS`，Runner 显示 Python `3.11.15`、PyTorch `2.5.1+cpu`、CUDA `false`。
- AT-002 与 AT-003 证据校验均为 `PASS`。
- `http://127.0.0.1:8787/healthz` 返回健康状态。
- 仪表盘显示 AT-002 `BLOCKED`、AT-003 `PASS / RESOLVED`。
- 浏览器缩放设为 100%，关闭无关窗口和通知。

## 0:00－0:30 开场

屏幕：仪表盘顶部。

讲解：

> AI 实验指标回退后，团队常用聊天助手给建议。建议本身不能证明谁执行了修改、有没有越权、结果能不能复核。LabOps Guard 用六个 Agent 角色把采证、诊断、规划、执行和验收拆开，并把每次交接写入证据链。

指向页面上的三条原则：无证据不诊断、无审批不执行、无验证不闭环。

## 0:30－1:05 三个案例

屏幕：仪表盘 AT-003 指标卡；随后向下展示 AT-002 和非法案例。

讲解：

> 系统保留三种结果。AT-002 的 Worker 缺少 torch，系统没有在线安装依赖，也没有用模拟指标替代，所以状态保持 BLOCKED。AT-003 把错误 checkpoint 切换到 best checkpoint，三次复算从 70.00% 恢复到 98.12%，Auditor 验证通过后才进入 RESOLVED。第三个案例试图修改 metric.py，策略拒绝动作，系统回滚并确认文件哈希恢复。

停留两秒，让评委看清三个状态。

## 1:05－1:40 六角色交接

屏幕：PPT 第 6 页，或仪表盘六角色区。

讲解：

> Commander 建立事件。Collector 只采白名单证据。Analyst 根据证据生成假设。Planner 制定最小实验。Safe Executor 只消费人工批准后的计划。Verification Auditor 独立复核并决定能否闭环。执行者没有宣布成功的权限。

补充一句：AT-003 记录了六次交接，每次都包含任务 ID、输入、输出、时间、状态和 Matrix event ID。

## 1:40－2:15 Planner 安全门

屏幕：PPT 第 9 页，或仪表盘计划区。

讲解：

> Planner 只允许修改 `eval_config.json` 的 checkpoint 字段。运行预算为 CPU、30 秒、三次复算、无网络。计划禁止修改 metric.py、验证数据、评测目标和原始工作区，并提前写明成功条件和回滚动作。

强调：人工批准发生在 Safe Executor 和 Runner 启动之前。

## 2:15－2:55 受限 Runner

屏幕：PPT 第 10 页，随后回到仪表盘 Runner 区。

讲解：

> Agent Worker 不安装 PyTorch，也不持有 Docker socket。Safe Executor 把结构化计划交给 localhost Gateway。Gateway 检查镜像、torch、checkpoint、配置、路径、预算和命令白名单。八项能力检查通过后，断网 CPU Runner 才启动。Runner 以非 root 身份运行，只读原始工作区，固定输出五类原始证据。

指向 `8 / 8 PASS` 和五个输出文件名。

## 2:55－3:35 Auditor 与第一次失败

屏幕：PPT 第 11 页，或仪表盘审计区。

讲解：

> Auditor 检查三次指标、保护文件哈希、变更路径、审批时序、manifest 和 Trace。第一次总 Trace 审计发现重复 Matrix event ID，系统拒绝收口。修正事件记录并重新校验后，审计结果才变成 CHAIN_OK / ACCEPTED。这里不声称 Auditor 在 Worker 内重跑模型，它验证的是 Runner 原始输出和完整执行证据。

不要跳过第一次审计失败。它能证明系统在证据链有问题时会停止。

## 3:35－4:10 证据包

屏幕：仪表盘证据与完整性区。

讲解：

> AT-003 证据包包含六角色、六次交接、26 个 artifact 和 10 条 Trace 事件。系统校验 ZIP、包内 manifest 和 Runner manifest 三层 SHA-256。Matrix 记录协作事件，MinIO 传递任务产物，Artifact 保存原始文件，Dashboard 只读取这些真实归档。

## 4:10－4:30 收尾

屏幕：PPT 第 14 页。

讲解：

> LabOps Guard 已开放 Schema、六类 Skill、Runner 契约、策略和两个真实 AgentTeams 案例。下一步会增加独立 Runner 二次评测和集中可观测。当前结论保持清楚：AT-002 是安全阻塞案例，AT-003 是合法修复案例，非法修改被拒绝并回滚。

## 现场故障预案

### 仪表盘无法启动

使用 PPT 第 13 页的真实仪表盘截图，随后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_evidence.ps1
```

向评委说明当前使用归档证据回放，不要把截图称为实时运行。

### Docker Runner 不可用

展示 AT-002 `BLOCKED`，说明安全停止是预期状态。不要现场安装依赖或修改镜像。

### AgentTeams 页面断开

展示证据包中的 `handoff_manifest.json` 与 `agentteams_trace.jsonl`。不要用角色提示词截图代替真实交接记录。
