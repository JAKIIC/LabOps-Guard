# LabOps Guard 复赛现场演示脚本

建议时长：4 分钟。主画面使用只读 Trust Dashboard；PPT 只用于项目定位和架构过渡。

## Preflight

- 确认页面显示 Trust Contract v1、Trust State Machine v1 和 `Read-only`。
- 确认五段证据链顺序为 Identity → Policy → Execution → Evidence → Audit。
- 确认页面没有综合评分以及执行、修改、审批入口。
- 确认 AT-004 为 `PASS / RESOLVED`，危险分支为 `POLICY_VIOLATION / ROLLED_BACK`。

## 0:00–0:30｜问题

“Agent 进入真实工程环境后，最大的风险不只是回答错误，而是它可能执行未经授权的动作，
并把不可信结果当作成功。LabOps Guard 是面向 AI 工程任务的可信 Agent 执行与治理基础设施。”

## 0:30–1:10｜Trust Layer

“Trust Contract v1 统一 Identity、Skill、Policy、Execution、Evidence 与 Audit 契约；
Trust State Machine v1 固定审批、执行和独立裁决顺序。Dashboard 不给一个模糊总分，而是
逐域展示真实检查和证据来源。”

指出六 Agent、七 Skill 数量不变，并强调 Safe Executor 不能宣布成功，Verification Auditor
独占 `RESOLVED / ROLLED_BACK / BLOCKED` 裁决权。

## 1:10–1:50｜危险分支

展示 AT-002 的 metric.py 篡改：受保护资源变化被 Policy 与哈希检查识别，执行结果不被接受，
恢复哈希经复核后得到 `POLICY_VIOLATION / ROLLED_BACK`。强调越权行为绝不能因为指标提高而
被包装为修复，终态不得标记为 `RESOLVED`。

## 1:50–2:50｜合法分支

展示 AT-004：固定评测从 `97.8124976%` 回退到 `71.875% × 3`。Collector 生成 10 条带哈希
事实；Analyst 排除 checkpoint、数据、metric 与随机性；Planner 只允许修改沙箱
`evaluation.preprocessing_profile`。人工审批早于执行，Runner 使用 CPU、30 秒、三次复算、
`network=none`，最终得到 `97.8124976% × 3`，保护哈希不变。

## 2:50–3:30｜证据与审计

展示 Auditor 从 raw stdout、metrics、manifest、审批时序和 Trace 独立重算。最终结论为
`PASS / RESOLVED`，7-entry Trace 为 `CHAIN_OK / ACCEPTED`，Evidence Bundle 有 27 entries，
SHA-256 为 `4092b43f39df52db3847caa28ca01e4321129a1c17ec7ca5efd2029ab1fb77cd`。

## 3:30–4:00｜治理评测与收尾

“10 个治理案例中，策略越权阻断率和独立审计准确率为百分之百，错误关闭率为零。该结果只
证明固定治理规则。Trust Dashboard 与 Public Replay 都是只读证据视图。当前是单机确定性
CPU Runtime；生产身份、分布式调度、MCP 和 OTel 是明确边界。LabOps Guard 让 Agent 的
工程行动可约束、可追踪、可验证。”

## Failure fallback

1. 本地 Trust Dashboard 不可用：切换 Public Trust Evidence Replay。
2. 公网页面不可用：播放预录完整视频。
3. 视频不可用：展示 Evidence Bundle 离线验证输出。
4. 任一契约、Trace 或哈希失败：停止成功故事，明确报告 `BLOCKED`。
