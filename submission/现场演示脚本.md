# LabOps Guard 现场演示脚本

建议时长：4 分钟。主画面使用只读仪表盘，PPT 用于架构和职责边界。

## Preflight

运行环境检查、三条证据校验和仪表盘启动脚本。确认 AT-004 显示
`AGENTTEAMS_RUN / PASS / RESOLVED`，AT-003 与 AT-002 分开展示。

## 0:00–0:30 问题

“AI 实验指标回退后，建议并不等于可信修复。我们需要证明谁基于什么证据做了什么，是否
越权，结果是否被独立复核。LabOps Guard 的原则是：无证据不诊断，无审批不执行，无验证
不闭环。”

## 0:30–1:05 真实事故与 RCA

展示 AT-004：固定 checkpoint、数据和 metric 的评测连续三次只有 71.88%，历史为 97.81%。
Collector 生成 10 条带哈希事实；Analyst 排除 checkpoint、数据和随机波动，将预处理配置
漂移列为 0.92 置信度的首要假设。

## 1:05–1:35 六角色协作

说明 Commander、Collector、Analyst、Planner、Executor、Auditor 的边界。强调每次交接都
记录 task/incident ID、输入、输出、时间、状态和真实 Matrix event；自然语言回复不是证据。

## 1:35–2:15 计划、审批与 Runner

Planner 只允许把沙箱预处理字段从 `train_augmented` 恢复为 `eval_standard`，CPU、30 秒、
三次复算、无网络，禁改 metric、数据、checkpoint、评测协议和原始工作区。人工批准早于
Runner 启动。Worker 不安装 torch、不持有 Docker socket；宿主策略检查 8/8、Runner 内能力
检查 10/10。

## 2:15–3:05 独立验证

三次候选达到 97.81%，只有一个沙箱字段变化，六组保护哈希不变。Auditor 从 raw stdout
和 manifest 独立重算，不复用 Executor 的“成功”声明。第一次 canonical trace 审计失败被
保留；补齐真实 Commander 事件后，7-entry 链才得到 `CHAIN_OK / ACCEPTED` 和
`PASS / RESOLVED`。

## 3:05–3:35 安全分支与经验闭环

AT-002 缺 torch 时安全 `BLOCKED`；AT-003 checkpoint 修复作为备用；非法 metric 修改被
拒绝并回滚。Incident Commander 把 AT-004 发布为独立 postmortem 和可搜索 case memory，
但它只提供未来诊断上下文，不能替代新事故证据。

## 3:35–4:00 收尾

“我们开放的是一套可复用治理协议：六角色、版本化 Skill、Runner 契约、五类证据和失败
闭环。当前是单机 CPU 演示；生产身份、调度和 OTel 后端是明确路线图，不会冒充已完成。”

## Failure fallback

- 仪表盘不可用：展示已校验 PPT 截图和证据校验输出，明确这是归档回放；
- Docker 不可用：展示 AT-002 `BLOCKED`，不现场安装依赖；
- AgentTeams 页面断开：展示 `handoff_manifest.json` 与 Trace，不用 Prompt 截图替代；
- 任一哈希失败：停止演示闭环并报告 BLOCKED。
